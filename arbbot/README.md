# ArbBot — بوت المراجحة بين المنصات

يراقب ArbBot أسعار العملات المشفرة على عدة منصات في نفس الوقت عبر **WebSocket**، ويكتشف متى يكون الشراء من منصة والبيع في أخرى مربحاً **بعد خصم كل التكاليف**، ثم ينفّذ الصفقة (محاكاةً افتراضياً)، ويعرض كل شيء على لوحة تحكم محلية.

---

> ## ⚠️ تحذير مهم — اقرأه قبل أي شيء
>
> 1. **شغّل البوت في وضع المحاكاة أسبوعاً كاملاً على الأقل** قبل التفكير في التداول الحقيقي، وراجع سجل الفرص والصفقات يومياً.
> 2. **الربح الصافي الفعلي للمراجحة بين المنصات صغير جداً، وتلتهمه بسهولة رسوم التداول، ورسوم السحب، والانزلاق السعري.**
>    الفوارق بين المنصات الكبرى على العملات الرئيسية عادةً **0.01%–0.05%**، بينما رسوم التداول وحدها **0.2%** (0.1% لكل طرف).
>    في تجربة حية على Binance وOKX وKuCoin لم يظهر أي فارق صافٍ موجب للعملات الخمس الافتراضية.
> 3. المراجحة تحتاج **رصيداً مسبقاً على كل المنصات** (USDT على منصة الشراء، والعملة نفسها على منصة البيع)، ويجب إعادة توزيعه دورياً، وهذا يكلّف رسوم سحب.
> 4. الأسعار تتغير في أجزاء من الثانية. قد يُنفَّذ طرف ويفشل الآخر، فيبقى لديك مركز مكشوف. البوت يحاول إغلاقه تلقائياً، لكن هذا ليس مضموناً.
> 5. هذا البرنامج أداة تعليمية وليس نصيحة مالية. أنت وحدك المسؤول عن أي خسارة.

## كيف يعمل

```
 Binance ─┐  WebSocket (دفتر الأوامر لحظياً)
 OKX     ─┼──► exchange_service ──► detector ──► executor ──► SQLite
 KuCoin  ─┘                           │             │
                                      └──► dashboard ◄┘  http://127.0.0.1:8000
```

1. **المراقبة** (`exchange_service.py`): اتصال WebSocket دائم مع كل منصة لكل زوج، يستقبل دفتر الأوامر (أفضل أسعار الشراء والبيع وكمياتها) لحظة تغيّره. **لا يوجد استقصاء دوري للأسعار.** عند انقطاع الاتصال يعيد المحاولة تلقائياً.
2. **الكشف** (`detector.py`): مع كل تحديث، يقارن كل منصتين في الاتجاهين: الشراء من A بسعر العرض (ask) والبيع في B بسعر الطلب (bid). يمر على عمق دفتر الأوامر ليعرف السعر الحقيقي لحجم صفقتك، ثم يحسب:

   ```
   الفارق الإجمالي = (أفضل bid في B − أفضل ask في A) ÷ أفضل ask في A
   الفارق الصافي   = الإجمالي − رسوم التداول (الطرفين) − رسوم السحب − الانزلاق
   ```
   - **رسوم التداول:** رسوم taker لكل منصة (`TAKER_FEES`).
   - **رسوم السحب:** كلفة إعادة توزيع الرصيد: سحب العملة من A إلى B، وسحب USDT من B إلى A. تُوزَّع على دفعة تداول (`REBALANCE_BATCH_USDT`).
   - **الانزلاق:** الفرق بين أفضل سعر ومتوسط السعر الفعلي لحجم الصفقة، مضافاً إليه هامش أمان (`SLIPPAGE_BUFFER_PCT`).

   تُعتبر فرصة فقط إذا تحققت كل الشروط التالية:
   - **الفارق الصافي ≥ العتبة** (`MIN_NET_SPREAD_PCT`، افتراضياً 0.3%)، والسعران حديثان.
   - **التحويل ممكن:** يمكن سحب العملة من منصة الشراء وإيداعها في منصة البيع، ونقل USDT في الاتجاه المعاكس. المنصات التي تنشر حالة التحويل (مثل KuCoin) تُفحص عند الاتصال ثم كل 30 دقيقة. فرق السعر على عملة لا يمكن نقلها ليس مراجحة، لأن العملة تبقى عالقة.
   - **الفرق ليس مريباً:** أي فارق إجمالي فوق 3% (`MAX_GROSS_SPREAD_PCT`) لا يُنفَّذ أبداً. فروق بهذا الحجم تعني عادةً شبكة موقوفة، أو شطباً، أو عملتين مختلفتين بنفس الرمز.

   كل فرصة تُسجَّل في SQLite.

   > مثال حقيقي من التشغيل: ONE/USDT أظهرت فارقاً **+13%** بين KuCoin وBinance، لأن KuCoin أوقفت الإيداع والسحب لها. قبل هذه الحماية، نفّذت المحاكاة 55 صفقة وهمية وسجّلت ربحاً وهمياً قدره 438$. في التداول الحقيقي كانت العملة ستعلق على KuCoin. الآن يظهر هذا المسار في اللوحة بعلامة «⛔ غير قابل للتنفيذ».
3. **التنفيذ** (`executor.py`): يرسل أمري الشراء والبيع **في نفس اللحظة** (`asyncio.gather`) كأوامر IOC محدودة السعر: تُنفّذ فوراً بسعر لا يتجاوز حداً آمناً، أو تُلغى. ثم يعالج النتيجة:

   | الحالة | ما يفعله البوت |
   |---|---|
   | نُفّذ الطرفان بالكامل | ✓ صفقة ناجحة |
   | تنفيذ جزئي (كمية الشراء ≠ كمية البيع) | يغلق الفرق بأمر سوق على المنصة التي نُفّذ فيها أكثر |
   | نجح طرف وفشل الآخر | يعكس الطرف الناجح فوراً |
   | فشل الإغلاق نفسه | يسجّل المركز المكشوف، ويُفعّل **الإيقاف الطارئ** تلقائياً |

4. **الحماية:** مهلة انتظار بين صفقات نفس المسار، وصفقة واحدة لكل عملة في نفس الوقت، وحد خسارة يومي يُفعّل الإيقاف الطارئ.

## التثبيت

يتطلب **Python 3.10 أو أحدث**.

```bash
# 1) من المجلد الرئيسي للمستودع
python -m venv .venv
source .venv/bin/activate          # على Windows:  .venv\Scripts\activate

# 2) المكتبات
pip install -r arbbot/requirements.txt

# 3) الإعدادات
cp arbbot/.env.example .env        # على Windows:  copy arbbot\.env.example .env
```

افتح ملف `.env` وعدّل ما تريد. للمحاكاة **لا تحتاج أي مفاتيح API**.

## التشغيل

```bash
python -m arbbot
```

ثم افتح المتصفح على **http://127.0.0.1:8000**.

| الأمر | الوظيفة |
|---|---|
| `python -m arbbot` | تشغيل البوت واللوحة، وتبدأ المراقبة فوراً |
| `python -m arbbot --no-autostart` | تشغيل اللوحة فقط، والمراقبة تبدأ بزر «بدء المراقبة» |
| `python -m arbbot --port 8080` | منفذ مختلف |
| `pytest tests/test_arb_core.py tests/test_arb_dashboard.py` | تشغيل الاختبارات |

للإيقاف اضغط `Ctrl+C`. ينتظر البوت انتهاء أي صفقة جارية قبل الإغلاق.

**الملفات التي ينشئها البوت:**
- `data/arbbot.sqlite3`: كل الفرص والصفقات، ويمكن فتحه بأي برنامج SQLite (مثل DB Browser for SQLite).
- `logs/arbbot.log`: سجل مفصّل لكل حدث، يدور تلقائياً عند 5 ميغابايت.

## لوحة التحكم

| القسم | ما يعرضه |
|---|---|
| الشريط العلوي | الوضع (✓ محاكاة / ⚠ حقيقي)، وحالة المراقبة، والاتصال، والأزرار |
| البطاقات | أفضل فارق صافٍ الآن (**خلفية خضراء إذا كانت فرصة**)، وعدد الفرص، والصفقات، والربح |
| المنصات | حالة الاتصال بكل منصة، وعدد التحديثات، وهل يوجد مفتاح API (نعم/لا فقط) |
| الأسعار اللحظية | سعر البيع والشراء لكل عملة على كل منصة. الأفضل بخط عريض أخضر، والسعر القديم بالأحمر |
| الفوارق الحالية | أفضل اتجاه لكل عملة: الإجمالي، والتكاليف، والصافي، والربح المتوقع. **أخضر = فرصة، أحمر = خسارة** |
| سجل الفرص | الوقت، والزوج، ومنصة الشراء، ومنصة البيع، والفارق الإجمالي، والفارق الصافي، والربح، وهل نُفّذت |
| الصفقات المنفّذة | النتيجة (كاملة / جزئية / معكوسة / فشل)، والكميات، والرسوم، والربح الفعلي |
| الأرصدة والمراكز | لقطة للقراءة فقط لأرصدة كل منصة، والصفقات الجارية، وأي مركز مكشوف |
| الأحداث | آخر ما حدث: بدء، أو إيقاف، أو تبديل وضع، أو إيقاف طارئ |

**الأزرار:**
- **▶ بدء المراقبة / ⏸ إيقاف المراقبة:** تشغيل أو إيقاف اتصالات WebSocket.
- **⇄ تبديل الوضع:** بين المحاكاة والحقيقي. الحقيقي يتطلب تأكيداً مزدوجاً، والتفاصيل في القسم التالي.
- **⛔ إيقاف طارئ:** يمنع **فوراً** إرسال أي أمر جديد، ويلغي أي أوامر مفتوحة على المنصات في الوضع الحقيقي. الصفقة التي بدأت قبل الضغط تكمل إغلاق طرفيها حتى لا تبقى مكشوفة. لإعادة التداول اضغط «إعادة تفعيل التداول» بعد مراجعة الأرصدة.

## الإعدادات

كل الإعدادات في ملف `.env`. القيم الافتراضية في `arbbot/.env.example`.

| المتغير | الافتراضي | الشرح |
|---|---|---|
| `PAPER_MODE` | `true` | `true`: محاكاة فقط، والتداول الحقيقي مقفل. `false`: يمكن تفعيل الحقيقي من اللوحة بتأكيد مزدوج |
| `EXCHANGES` | `binance,okx,kucoin` | منصتان على الأقل من: `binance`, `okx`, `bybit`, `kucoin` |
| `SYMBOLS` | `BTC/USDT,ETH/USDT,SOL/USDT,XRP/USDT,DOGE/USDT` | الأزواج المراقبة |
| `MIN_NET_SPREAD_PCT` | `0.3` | أقل فارق صافٍ (%) لاعتبار الفرصة قابلة للتنفيذ |
| `TRADE_SIZE_USDT` | `100` | حجم كل صفقة بالدولار |
| `SLIPPAGE_BUFFER_PCT` | `0.05` | هامش أمان إضافي (%) لتحرك السعر أثناء إرسال الأوامر |
| `INCLUDE_WITHDRAWAL_FEE` | `true` | خصم كلفة إعادة توزيع الأرصدة |
| `REBALANCE_BATCH_USDT` | `2000` | حجم التداول بين عمليتي إعادة توزيع. اجعله = `TRADE_SIZE_USDT` لأكثر تقدير تحفظاً |
| `MAX_QUOTE_AGE_MS` | `3000` | تجاهل الأسعار الأقدم من هذا (مللي ثانية) |
| `TAKER_FEES` | 0.1% للجميع | رسوم التداول لكل منصة (JSON). **ضع مستوى حسابك الحقيقي** |
| `WITHDRAWAL_FEES` | قيم تقريبية | رسوم السحب لكل عملة بوحدتها (JSON). **تحقق من القيم الحالية على كل منصة** |
| `MAX_GROSS_SPREAD_PCT` | `3.0` | أي فارق إجمالي أكبر من هذا يُعتبر مريباً ولا يُنفَّذ |
| `TRANSFER_REFRESH_MINUTES` | `30` | كل كم دقيقة تُقرأ حالة الإيداع والسحب |
| `DEFAULT_WITHDRAWAL_FEE_USDT` | `1.0` | رسوم سحب تقديرية بالدولار لأي عملة غير موجودة في `WITHDRAWAL_FEES`، حتى لا تُحسب مجاناً |
| `PRICE_TOLERANCE_PCT` | `0.2` | أقصى تجاوز للسعر المقتبس في أمر IOC، بحد أقصى نصف الفارق الصافي |
| `COOLDOWN_SECONDS` | `10` | انتظار قبل تكرار نفس المسار |
| `MAX_DAILY_LOSS_USDT` | `50` | الإيقاف الطارئ عند هذه الخسارة خلال يوم (UTC) |
| `PAPER_QUOTE_BALANCE` | `10000` | رصيد USDT وهمي على كل منصة |
| `PAPER_BASE_VALUE_USDT` | `5000` | قيمة العملات الوهمية على كل منصة |
| `PAPER_FAIL_RATE` | `0` | احتمال (0 إلى 1) فشل طرف عشوائياً، لاختبار معالجة الأخطاء |
| `USE_PUBLIC_DATA_ENDPOINTS` | `true` | استخدام عناوين البيانات العامة الرسمية التي تعمل في مناطق أكثر (انظر [حل المشاكل](#حل-المشاكل)) |
| `DASHBOARD_HOST` / `DASHBOARD_PORT` | `127.0.0.1` / `8000` | عنوان اللوحة |
| `DB_PATH` / `LOG_FILE` | `data/…` / `logs/…` | مسارا قاعدة البيانات والسجل |

**مثال لتقدير الربح بالأرقام الافتراضية** (صفقة 100$ على BTC):

| البند | القيمة |
|---|---|
| الفارق الإجمالي النموذجي | +0.02% |
| رسوم التداول (0.1% × 2) | −0.20% |
| السحب: (0.0002 BTC × 84,000$ + 1 USDT) ÷ 2,000$ | −0.89% |
| هامش الانزلاق | −0.05% |
| **الصافي** | **−1.12%** ← لا فرصة |

## التداول الحقيقي

> لا تفعل هذا قبل أسبوع محاكاة على الأقل، وقبل فهم كل ما في قسم التحذير.

للتداول الحقيقي **ثلاثة أقفال** متتالية:

1. **ملف `.env`:** ضع `PAPER_MODE=false` ومفاتيح API لكل منصة في `EXCHANGES`، ثم أعد تشغيل البوت.
2. **اللوحة:** زر «⇄ تبديل الوضع» يطلب تأكيدين منفصلين:
   - التأكيد الأول: تحديد مربع «أفهم أن الأوامر حقيقية وأنني قد أخسر المال»،
   - التأكيد الثاني: كتابة الكلمة `LIVE` في الخانة.
3. **فحص المفاتيح:** قبل أي أمر، يتصل البوت بكل منصة ويقرأ الرصيد. إذا فشل أي مفتاح يبقى في المحاكاة.

وحتى بعد التفعيل، يبدأ البوت دائماً في وضع المحاكاة عند كل تشغيل جديد.

**إعداد المفاتيح بأمان:**
- أنشئ مفتاحاً بصلاحية **التداول الفوري (Spot Trading) فقط**. **لا تفعّل صلاحية السحب أبداً.**
- قيّد المفتاح بعنوان IP جهازك من إعدادات المنصة.
- OKX وKuCoin تحتاجان أيضاً كلمة مرور المفتاح (`*_API_PASSWORD`).
- وزّع الرصيد مسبقاً: USDT والعملات المراقبة على كل منصة.

## الأمان

- **المفاتيح في `.env` فقط**، ولا تُكتب داخل الكود. الملف مستثنى من git.
- **اللوحة لا تعرض أي حرف من المفاتيح**: تعرض فقط «✓ مفتاح موجود» أو «بلا مفتاح». الاختبارات تتحقق من ذلك.
- **اتصالات بيانات الأسعار عامة**: لا ترسل مفاتيحك إليها أبداً. العملاء الموقّعون يُنشؤون فقط عند التحويل للوضع الحقيقي.
- **اللوحة محلية وبلا تسجيل دخول**، ومحمية بعدة طبقات:
  - تعمل على `127.0.0.1` فقط افتراضياً.
  - ترفض أي طلب باسم مضيف غير محلي، وهذا يحمي من هجوم DNS rebinding.
  - أزرار التحكم تتطلب ترويسة خاصة لا يستطيع أي موقع آخر في متصفحك إرسالها، وهذا يحمي من هجوم CSRF.
  - ترفض اتصالات WebSocket القادمة من مواقع أخرى.
- **لا تفتح اللوحة على الشبكة** (`DASHBOARD_HOST=0.0.0.0`) إلا داخل شبكة موثوقة أو عبر VPN، وأضف اسم الجهاز إلى `DASHBOARD_ALLOWED_HOSTS`.

## هيكل الكود

```
arbbot/
├── config.py            الإعدادات من .env، وإخفاء المفاتيح، والسجلات
├── models.py            دفتر الأوامر، والفرصة، وحساب متوسط السعر عبر العمق
├── exchange_service.py  اتصالات WebSocket (ccxt.pro)، وإعادة الاتصال
├── detector.py          حساب الفارق الإجمالي والصافي، وكشف الفرص
├── executor.py          التنفيذ المتوازي، والتنفيذ الجزئي، والفشل، والمحاكاة والحقيقي
├── storage.py           قاعدة بيانات SQLite (جدولا الفرص والصفقات)
├── bot.py               الربط بين الوحدات، والأوضاع، والإيقاف الطارئ، والأرصدة
├── dashboard.py         FastAPI: الصفحة، وواجهة API، وWebSocket للوحة، والحماية
├── templates/index.html واجهة اللوحة (عربية، فاتح/داكن، تعمل على الهاتف)
├── __main__.py          نقطة التشغيل: python -m arbbot
├── requirements.txt
└── .env.example
```

كل شيء غير متزامن (asyncio). عمليات قاعدة البيانات تعمل في خيط منفصل حتى لا تعطّل استقبال الأسعار.

## حل المشاكل

| المشكلة | الحل |
|---|---|
| منصة «غير متصلة» مع خطأ 451 أو 403 | المنصة تحجب منطقتك. Binance: اترك `USE_PUBLIC_DATA_ENDPOINTS=true` (يستخدم `data-stream.binance.vision`). Bybit محجوبة في بعض الدول: أزلها من `EXCHANGES` |
| OKX: انتهاء المهلة (timeout) | بعض الشبكات تحجب المنفذ 8443. مع `USE_PUBLIC_DATA_ENDPOINTS=true` يستخدم البوت المنفذ 443 |
| فارق كبير جداً عليه «⛔ غير قابل للتنفيذ» | التحويل موقوف على إحدى المنصات، أو الفارق فوق 3%. هذه ليست فرصة، والبوت يتجاهلها عمداً |
